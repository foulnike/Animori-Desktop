# Архитектура

Настольное приложение AniMori на Tauri 2. Ядро — `src/shared/`, экраны —
`src/app/`, оболочка — `src-tauri/`.

Приложение ведёт только аниме. Манги нет: ни экранов, ни отборов, ни запросов.
Словаря перевода интерфейса нет — интерфейс свой.

Данные склеиваются из нескольких источников: каталог и списки — AniList,
русские названия — датасет `foulnike/animori-data`, чего в нём нет — anime365
и Шикимори, описания там же, персонажи и авторы — Шикимори, музыка —
AnimeThemes, видео — Aniliberty и Kodik.

Список односторонний: он приезжает из AniList по входу, с Шикимори по нику
и файлом выгрузки MyAnimeList (тот же файл отдаёт Шикимори).
Правки живут на устройстве и на сервер не уходят — ни очереди, ни отправщика
в коде нет. Наружу список попадает выгрузкой в XML и копией в облако,
по действию человека. Подробно — `STORAGE.md`.

## Слои

```
app/                       знает разметку
        ↓
shared/api/ → shared/bridge/
        ↓          ↓
      core/  ←─────┘
        ↓
      utils/
```

Правила зависимостей и инварианты — в `CONVENTIONS.md`.

## Мост

`src/shared/bridge/` прячет платформу за одним контрактом. Ядро не спрашивает,
где оно работает.

| Группа             | Как устроено                                       |
| ------------------ | -------------------------------------------------- |
| `storage`          | плагин store, файл `animori-settings.json`         |
| `http`             | плагин http, запрос идёт из Rust, без CORS         |
| `anilist`          | команда `animori_anilist_query`                    |
| `clipboard`        | плагин clipboard-manager                           |
| `shell`            | перезагрузка, полный экран, внешняя ссылка         |
| `files`            | `animori_file_read` / `animori_file_write`         |
| `exportFile`       | выбор папки и запись файла: XML и звук темы        |
| `proxyDiagnostics` | щуп прокси из Rust, живой запрос и состояние входа |

У `files` и `exportFile` есть признак `available`: вне оболочки обе группы есть,
но ничего не делают. Проверяет его вызывающий.

`anilist` отделена от `http`: адрес и пропуск живут только в Rust, наверх идёт
тело запроса и просьба его подписать. Токен не покидает оболочку.

`files` отдаёт наружу имя, а не путь: каталог выбирает оболочка. Имён два —
`animori-snapshot.json` и `animori-dataset.json`, белый список в `files.rs`.
Потолок записи — 8 МБ. Запись идёт во временный файл с переименованием.

`exportFile` устроена наоборот: путь выбирает человек диалогом, сторожем
служит окончание имени. Единственное место, где программа пишет вне своего
каталога, и пишет туда только `.xml`.

`proxyDiagnostics` отвечает на вопрос «почему ничего не грузится» двумя
шагами: щуп из Rust (`src-tauri/src/proxy.rs`) и живой запрос тем же каналом
(`api/proxy-check.ts`).

## Слой запросов

### Ограничитель темпа

`api/rate-limit.ts` заводит ограничитель на источник, а не на домен: лимит
считается по IP, и зеркала делят один бюджет.

| Источник                        | Интервал | Потолок за минуту           |
| ------------------------------- | -------- | --------------------------- |
| Шикимори, anime365, AnimeThemes | 300 мс   | 60                          |
| GitHub: опись и файлы датасета  | 300 мс   | 60                          |
| Aniliberty                      | 300 мс   | 60                          |
| AniList                         | 100 мс   | старт 30, предохранитель 90 |

У Шикимори и anime365 общий ограничитель: источники стоят в одной цепочке
добычи имени. Исключение — `shikimori-user.ts`: единичные запросы по кнопке
идут мимо ограничителя.

`acquireSlot()` — единственный вход. Слоты выдаются по одному через шлюз.
Сверх минутного окна держится секундное: три запроса в секунду в первые
десять секунд после пуска, дальше восемь.

Интервал у AniList выведен из потолка (`deriveInterval`). Плавающий потолок
включён только у AniList: остальные источники заголовков не присылают. Ответ
429 режет потолок вдвое и закрывает рост на пять минут; ниже шести запросов
в минуту потолок не опускается.

### AniList

`api/anilist.ts` — единственная точка GraphQL и держатель общей паузы.
Запросов на запись нет вовсе.

Заголовки читаются из любого ответа, включая ошибки, в любом регистре имени:
мост в Rust имена понижает. `x-ratelimit-limit` учит потолок, нулевой
`x-ratelimit-remaining` ставит паузу до `x-ratelimit-reset`, но не длиннее
минуты.

Ответ 429: пауза по `retry-after` либо пять секунд, потолок урезается, повтор
до трёх раз. Отказ сервера (403, 408, всё от 500): пауза 30 секунд
с удвоением до пятнадцати минут, удачный ответ обнуляет серию. Паузу дольше
десяти секунд вызов не высиживает, а бросает ошибку с остатком.

403 неоднозначен: его AniList отдаёт и при закрытии доступа, и когда сервис
лёг. При отказе в журнал выписываются заголовки `cf-ray`, `cf-mitigated`,
`cf-cache-status`, `retry-after`, `x-ratelimit-*` и `server`. Тела ответа
в журнале нет.

### Источники

- `titles.ts` — выборщик русского названия. Порядок задан настройками:
  `titlePrimary` по умолчанию anime365, `titleFallback` — Шикимори.
  `resolveTitle(malId)` отдаёт название, описание, ссылку, имя источника,
  оценку MAL и распределение голосов Шикимори. BBcode вычищается на входе.
  Разрез «имя» и «карточка» сделан в `core/media-title.ts`: `NAME1_` и `RU4_`.
- `shikimori.ts` — `fetchShiki` с перебором зеркал, возвращает сработавший
  домен.
- `shikimori-media.ts` — стратегия поверх транспорта: карточка одна на
  открытие, имена для сеток пачками по пятьдесят.
- `shikimori-list.ts` — чужой список по нику, второй источник переноса.
- `shikimori-search.ts` — русский поиск, только раздел аниме.
- `shikimori-people.ts` — имена людей по схожести строк; при низкой уверенности
  кандидат проверяется по общим тайтлам. Раздел манги оставлен: кредиты по
  манге опознают человека.
- `shikimori-user.ts` — чужой профиль и его список.
- `anime365.ts` — русские названия и описания. Счётчик ошибок гасит источник
  до конца сессии.
- `anilist-*.ts` — списки, карточка, выписки пачками, полки главной, люди,
  работы автора, расписание выхода серий. Вид тайтла в запросах — слово
  `ANIME` в теле запроса, а не переменная.
- `media-shots.ts` — кадры и ролики: галерея Шикимори одним заходом, запасной
  источник — `streamingEpisodes` карточки. Отказ источника не кэшируется.
- `animethemes.ts` — темы через GraphQL: отказ приходит с кодом 200
  и лежит в поле `errors`.
- `kodik.ts`, `aniliberty.ts`, `video-sources.ts` — видео, см. раздел «Видео».
- `yandex-disk.ts` — облачная копия списка.

Адресов у Шикимори два — `shikimori.rip` и `shikimori.io`, список
`SHIKI_DOMAINS` в `core/constants.ts`.

## Хранение

Пять мест, различает их цена потери.

| Что                           | Где                      | Если потеряется         |
| ----------------------------- | ------------------------ | ----------------------- |
| Ответы сети, русские карточки | IndexedDB                | добудется заново        |
| Снимок списка                 | хранилище моста          | правки взять негде      |
| Второй экземпляр снимка       | файл приватного каталога | остаётся главный        |
| Датасет названий              | файл приватного каталога | скачается заново        |
| Копия списка                  | облако владельца ключа   | остаётся местный снимок |

Ссылки на видеопоток не хранятся нигде: они подписаны и просроченными
становятся сами.

### IndexedDB

База `AniMoriSuperDB`, версия 6, три стора: `mediaCache` по строковому ключу,
`malCache` и `franchiseCache` по числовому.

| Префикс    | Что лежит                               |
| ---------- | --------------------------------------- |
| `NAME1_`   | русское имя тайтла                      |
| `NONAME1_` | отказ: русского имени нет               |
| `RU4_`     | русская карточка: имя, описание, оценки |
| `LOOK3_`   | облик тайтла: обложка, цвет, части      |
| `MED3_`    | карточка Шикимори                       |
| `CHR3_`    | персонажи                               |
| `STF4_`    | авторы                                  |
| `THEMES2_` | музыкальные темы                        |
| `RATE1_`   | оценки площадок                         |
| `PLAY1_`   | метка доступности видео                 |
| `ALIB1_`   | соответствие Aniliberty                 |
| `SHOT1_`   | кадры и ролики тайтла                   |

Цифра в префиксе — версия формы записи. Меняется форма — растёт цифра, старые
записи перестают находиться. `getDbStats` считает каждый вид отдельно,
неузнанное складывает в `other`.

Префиксы `KODIK1_`, `SHELF2_`, `RECS1_` и `GENRE1_` в таблице не перечислены
и считаются остатком `other`. Ключ `TAGS1_all` — одна запись на весь словарь
тегов.

Единого срока годности нет: `CACHE_TIME` бесконечен, срок у каждого вида свой,
лежит в `core/cache-life.ts` и проверяется при чтении (`isFresh`). Карточка
завершённого тайтла живёт неделю, идущего — сутки, полка «сейчас выходит» —
шесть часов, поиск и лента — пятнадцать минут, люди и жанры — бессрочно,
кадры и ролики — месяц. Разброс ±20 % считается от ключа, а не случайно.

Открытие базы разрешается всегда и ровно один раз: соединением, `null` по
ошибке или `null` по таймауту в семь секунд.

### Снимок

Одна запись в хранилище моста, `AM_SNAPSHOT`, плюс второй экземпляр в файле
приватного каталога. Код разведён: снимок — `core/snapshot.ts`, общее звено
записей — `core/store-chain.ts`. Звено отдельное: у записей один черёд.

Форма снимка — шестая версия. Повышение версии обесценивает все местные
снимки, и список при первом запуске переносится заново.

## Слой данных

Порядок пуска держит `app/main.ts`:

1. `loadSettings()` — настройки.
2. `startAppearance()` — тема.
3. `installGlobalErrorHandlers()` — перехватчики.
4. монтирование `App`, сразу за ним `hideBoot()`.
5. `initCollection()` — подъём снимка.
6. `initDatasetNames()` и `updateDatasetNamesInBackground()`.

Настройки первыми: иначе первая перерисовка идёт на значения по умолчанию.
Тема до первой отрисовки. Перехватчики после настроек и до монтирования.
Коллекция поднимается после монтирования: чтение снимка задержало бы первую
отрисовку. Заставка старта (`#boot`) лежит в `src/app/index.html` отдельным
узлом рядом с корнем и снимается сразу после монтирования.

```
экраны
  ├─ collection-view.ts  отборы и счётчики (только чтение)
  ├─ adult.ts            единый отбор 18+
  ├─ media-title.ts      русские карточки → db.ts, api/titles.ts
  ├─ media-looks.ts      обложка, цвет, части → db.ts
  ├─ media-parts.ts      порядок записей каталога при одном номере MAL
  ├─ media-search.ts     поиск по своему списку и по чужому каталогу
  ├─ franchise.ts        дерево франшизы → shikimori.ts
  ├─ ratings.ts          оценки Шикимори и MAL
  ├─ person-title.ts     русские имена людей
  ├─ rich-text.ts        описания в разметку показа
  └─ playable.ts         метка доступности видео: очередь и работники
collection.ts  ← api/anilist-list.ts, api/shikimori-list.ts, api/mal-import.ts; → snapshot.ts
mal-xml.ts     сборка и разбор опися MAL; файл пишет app/save-file.ts, читает app/load-file.ts
cloud.ts       ← collection.ts;        → api/yandex-disk.ts
snapshot.ts → store-chain.ts   общее звено записей

 dataset-names.ts  слепок выпуска на диске; сроки — cache-life.ts
 proxy.ts          настройка канала (чистый: его читает мост)
 proxy-settings.ts то же со стороны разметки + вопрос о перезапуске
 net-health.ts     учёт доступности источников: суждение и пробы
 video.ts          общий слой источников видео
```

Два модуля в `core/` не имеют вызывающих: `accent.ts` и `qr.ts`.

### collection.ts

Записи держатся словарём по номеру тайтла. Правка идёт через `editEntry()`
и никуда не отправляется: ложится в память и в снимок. Правка неизвестного
тайтла создаёт пустую запись.

Перенос с сервера бывает двух видов, выбирает человек: `mergeFromServer`
(основа — ответ сервера, чего там нет, остаётся) и `replaceFromServer`
(список становится ровно таким, как на сервере). Замещение спрашивает
подтверждение, слияние нет.

Тот же выбор стоит при переносе с Шикимори (`pullFromShikimori`) и из файла
выгрузки MAL (`pullFromMalFile`), с двумя оговорками: хозяин списка не
меняется, и ответ забирается целиком до изменения памяти. У файла своя
черта: метки правки в записи может не быть (выгрузка Шикимори её не пишет),
и тогда запись считается старейшей. Рядом — `unlinkCollection`
и `forgetCollection`.

### media-title.ts

Путь чтения имени четырёхуровневый: память запуска, датасет, склад, сеть.
Ответ «такого номера в файле нет» запоминается, в сеть за ним не идут.
Путь описания и оценок — трёхуровневый: память, склад карточек, сеть.

В памяти запоминается и отсутствие перевода. Сетевой сбой не запоминается.
Пачка добывается по очереди; соответствия MAL берутся одним запросом на пачку.

### Пути наружу

- `core/mal-xml.ts` собирает опись в формате MyAnimeList, `app/save-file.ts`
  отдаёт её оболочке. В обратную сторону тот же модуль разбирает чужой
  файл, `app/load-file.ts` читает его с диска (gzip распознаётся по подписи),
  а `api/mal-import.ts` сводит номера MAL с AniList.
- `core/cloud.ts` и `core/cloud-file.ts` кладут копию списка в облако
  и забирают обратно слиянием или замещением.

## Прокси и учёт сети

AniList недоступен напрямую из России, поэтому канал — часть приложения.

- `core/proxy.ts` — настройка и ключи хранилища. Модуль чистый: его читает
  и прикладной код, и мост.
- `core/proxy-settings.ts` — та же настройка со стороны разметки плюс вопрос
  о перезапуске. Разбор значений обязан совпадать с Rust: ключи читают
  `proxy.rs`, `anilist.rs` и этот модуль.
- `core/net-health.ts` — единое суждение о доступности (`getOutage`) и одна
  проба (`runProbes`).

Настройка не применяется на ходу: канал задаётся аргументом при запуске окна,
нужен перезапуск. Пароль прокси лежит в `animori-settings.json` открытым
текстом.

Формулировки: ни одного адреса прокси в коде нет, в интерфейсе и документации
это настройка соединения.

## Оболочка

### Окна

Окно `main` грузит сборку из `dist/app`. Окно `login` держит форму входа.
Больше окон нет. `app.windows` в `tauri.conf.json` пуст: оба окна создаются
кодом.

Внешние ссылки уходят в системный браузер командой `animori_open_external`.
Перехвата навигации в коде нет: окно грузит только свою сборку. Глобального
объекта Tauri в окне нет (`withGlobalTauri: false`). Политика содержимого
не задана (`csp: null`).

### Команды и права

Разрешения одни — `capabilities/default.json`. Права выданы только окну `main`:
окно входа грузит чужую страницу.

| Команда                                                          | Зачем                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------- |
| `animori_anilist_query`                                          | запрос к AniList из Rust                                 |
| `animori_auth_start`, `_submit`, `_status`, `_logout`            | вход, ручная вставка пропуска, срок, выход               |
| `animori_file_read`, `animori_file_write`                        | снимок списка и датасет в профиле                        |
| `animori_export_pick_dir`, `animori_export_write`                | выгрузка XML                                             |
| `animori_track_pick_dir`, `animori_track_write`                  | запись звукового файла темы                              |
| `animori_proxy_status`, `animori_proxy_probe`                    | исход настройки сети и проба адреса                      |
| `animori_open_external`                                          | ссылка в системный браузер                               |
| `animori_cast_panel`                                             | системная панель трансляции, только Windows              |
| `animori_reload`, `animori_restart`, `animori_toggle_fullscreen` | перезагрузка страницы, перезапуск процесса, полный экран |

`animori_reload` и `animori_restart` путать нельзя: **перезагрузка страницы
не применяет прокси.** Ключи запуска WebView2 читаются один раз, при создании
первого окна.

Внешние адреса для `http:default` перечислены там же, включая
`cloud-api.yandex.net` и раздатчики файлов Яндекса. Список живёт до сети:
промах плагин отклоняет до всякого запроса.

Новая команда — всегда три места: `invoke_handler` в `src/lib.rs`, `COMMANDS`
в `build.rs` и `permissions` в `capabilities/default.json`.

### Вход

Форма открывается в окне `login`, которое идёт через наш прокси. Пропуск
возвращается на `http://127.0.0.1:48513/relay`: приёмник слушает только
петлю и гаснет через пять минут. Разметка видит только факт входа и срок.
Ручная вставка — запасной путь.

**Адрес возврата задан не в репозитории**, а в консоли разработчика AniList.
При смене адреса приёмника правится консоль, а не исходник.

### Прокси

Трафик идёт двумя каналами: страница — через ключи запуска WebView2, запросы
из Rust — через опцию клиента. `proxy.rs` сводит всё к одному из четырёх
исходов: выключено, неверные данные, адрес не отвечает, применено. Исход
доступен интерфейсу командой `animori_proxy_status`; читатель — `ProxyBox.vue`.

Прокси, который соединение принимает и не пускает наружу, TCP-щупом не
отличить: второй шаг живёт в ядре (`api/proxy-check.ts`).

За пределами Windows исхода `Applied` не бывает: переменную окружения читает
только WebView2. `proxy_auth.rs` подставляет логин с паролем на событие
базовой авторизации, только под Windows.

### Сборка

Режим один: корень `src/app`, выход `dist/app`.

- `@bridge-impl` → `shared/bridge/TauriBridge.ts`.
- `@/api`, `@/bridge`, `@/core`, `@/utils`, `@` — соответствия каталогов.
  Точные пути идут раньше общих, `@` последним. Те же соответствия —
  в `tsconfig.json` и `tsconfig.shared.json`.
- `__ANIMORI_PLATFORM__` = `'app'`, `__ANIMORI_VERSION__` — из `package.json`.
- `minify: 'esbuild'`, `target: 'es2022'`, `emptyOutDir: true`.
- `hls.js` → `dist/hls.light.mjs`: плеер берёт лёгкую сборку.

`beforeBuildCommand` и `beforeDevCommand` зовут `npm run build:app`;
`frontendDist` смотрит на `dist/app`. `build:app` начинается с `typecheck:all`.
`npm test` гоняет vitest по `tests/**/*.test.ts`, мост подменяется
(`@bridge-impl` → `tests/mocks/bridge.ts`), окружение — `happy-dom`.

Номер версии один, в `package.json`; `tauri.conf.json` берёт его строкой
`"version": "../package.json"`. Теги выпуска — `app-<версия>`.

### Выпуск и обновление

Установщик один — NSIS, рядом подпись `.sig`. Обновление проверяется по описи
`latest.json` из `releases/latest`, режим установки `passive`. Ключи подписи
лежат в секретах сборки; неподписанное обновление клиент не примет.

Профиль программы — `AppData\Roaming\com.foulnike.animori`:
`animori-settings.json` (настройки, пропуск, ключ облака),
`animori-snapshot.json`, `animori-dataset.json`.

Имя каталога профиля — `identifier` из конфига; его смена равносильна потере
настроек у всех установленных копий.

## Экраны

Экран ничего не знает про сеть и хранение: читает память через
`collection-view.ts`, меняет список через `editEntry()`, имена берёт у
`media-title.ts`, облик — у `media-looks.ts`, взрослое отбирает через
`adult.ts`. Подписи — в `app/labels.ts`.

### Адреса

Девять экранов: главная, списки, история, поиск, карточка тайтла, студия,
плеер, настройки, журнал. Три с номером в адресе: карточка, студия, плеер.

В меню пять: главная, списки, история, поиск, настройки. На карточку и студию
попадают из списков, поиска и чипов; на плеер — кнопкой «Смотреть»; журнал
открывается адресом `#/log`.

Имена, меню и заголовки лежат в `router/routes.ts` отдельно от роутера. Там же
— глубина экрана: по ней смена экрана получает направление.

Отбор списка в адрес не пишется: закладка, порядок и слово живут в
`lists-keep.ts`, жанр витрины — в `home-keep.ts`.

### Тема и токены

`styles/theme.css` — единственное место цвета, радиуса, тени, стекла
и длительности. Тем три: тёмная, светлая и AMOLED. Тема живёт атрибутом
`data-am-skin` на `<html>`; выбор хранится ключом `am_appearance`.

Акцент живёт дважды: `--am-accent` и `--am-accent-2` — готовые цвета,
рядом `--am-accent-rgb` и `--am-accent-2-rgb` — триплеты для альфы.
`amApplyAccentToDom()` из `shared/core/accent.ts` в слое приложения звать
нельзя: она подменяет цвет на триплет.

Размеры: `--am-tile` (clamp 148–216), `--am-ctl` (40), `--am-touch` (44),
`--am-page-max`, `--am-side`, `--am-side-slim`. Формы: `--am-r-s…xl`,
`--am-r-cap`, `--am-r-leaf`, `--am-r-drop`, `--am-r-blob`. Стекло:
`--am-glass`, `--am-glass-2`, `--am-glass-deep`, `--am-edge`, `--am-veil`.
Длительности: `--am-fast`, `--am-mid`, `--am-slow`, `--am-ease`,
`--am-ease-soft`.

Стекло не кладут на списковые строки: сотня `backdrop-filter` за кадр.
Полоса музыки — исключение, у неё `--am-glass-deep`.

Обводка фокуса задана правилом на `:focus-visible`. Гасят её два правила:
`.am-input:focus` и `.am-pick:hover, .am-pick:focus`. `.am-pick` в общей теме —
правило для системного `<select>`.

`@media (prefers-reduced-motion: reduce)` гасит всё движение.

### Состав

- **HomeScreen** — витрина рекомендаций и календарь выхода. Полку просит
  `core/recs.ts`: страница выборки приходит с запасом в тридцать плиток,
  показываются четырнадцать, остальное закрывает отметки «не интересно»,
  а кончился запас — берётся следующая страница. Отбор показа — своё,
  скрытое, взрослое — применяется на выдаче, поэтому полка не пустеет
  от отметок, а тумблер взрослого действует в обе стороны. Скрытые
  рекомендации копятся в `am_recs_hidden` с потолком 500; очистка памяти
  снимает их вызовом `clearHidden()`. Вкус считается по жанрам записей
  с оценкой 8 и выше.

  Календарь считается в `home-calendar.ts`: неделя берётся запросом
  `airingSchedules` одним заходом. Взрослый выход отсеивается на входе,
  до прогревов; метка едет вместе с расписанием.

- **HistoryScreen** — что смотрели, свежее вперёд и по дням. Записи пишет
  плеер в `player-keep.ts`; заголовок и обложка едут в записи с просмотра.
- **ListsScreen** — строки строятся в три шага: отбор и порядок по памяти,
  затем облик пачкой, затем русские имена по десять. Имя ищется по цепочке:
  русское со склада, ромадзи снимка, английское, ромадзи облика, номер.
  Смотритель ловит метку конца за 600 пикселей и ставит рядом кнопку
  с остатком. Поиск по своему списку идёт в памяти, ждёт четверть секунды
  и показывает не больше шестидесяти находок. Счётчики считают видимое:
  `countByStatus({ hideAdult: true })`.
- **SearchScreen** — слово выбирает источник: латиница в AniList, кириллица
  в Шикимори с переводом находок по номерам MAL. У русского пути нет второй
  страницы.
- **MediaScreen** — карточка. Русское имя показывается сразу из датасета.
  Описание — одной колонкой, разметку рисует `RichText`. Франшиза —
  хронология частей со Шикимори. Карточка видит свою память и ответ сервера
  и показывает свою; расхождение названо подсказкой. Раскладка — две равные
  колонки. Полка франшизы — строка на запись каталога, а не на узел Шикимори:
  у раздробленной части номер MAL общий, ключ строки — номер записи.

  Кадры и трейлер — плитка `ShotBox`: кадр трейлера полосой, под ним сетка
  четыре на два, последняя клетка — счётчик. На широкой доске кадр встаёт
  боком: сетка две трети плитки, трейлер треть. Высоты в ряду сводит
  растягивание. Плитка без соседа занимает ряд целиком. Пока картинки едут,
  на их месте `.am-skeleton`.

  Музыка — полоса `TuneBox` внизу окна: пуск, соседние темы, подпись, время,
  перемотка. Список тем и громкость — в окне по кнопке справа.

- **PlayerScreen** — просмотр, см. раздел «Видео».
- **StudioScreen** — работы студии сеткой. Шапка — квадрат с первой буквой
  имени.
- **SettingsScreen** — блоки: вход, оформление, названия и перевод, показ
  и плеер, сеть и прокси (`ProxyBox.vue`), свои данные, облачная копия,
  о программе. Настройка пишется сразу при переключении. Опасное спрашивает

  не запоминает. Состояние датасета — в «О программе».
- **LogScreen** — журнал запуска. Строки на плоской подложке с засечкой
  слева по роду записи; родов пять.

### Доступность источников

Учёт идёт по идентификаторам: `anilist:graphql`, `shikimori:<домен>`,
`anime365:<домен>`, `animethemes`, `aniliberty`. `core/net-health.ts` не знает
ни одного адреса. Источник считается проблемным после двух неудач подряд;
отказ авторизации, 429 и отмена не учитываются, 404 считается успехом.

Отдельной проверки источников нет: модуль считает исходы чужих запросов.
Последовательный перебор зеркал — в `api/shikimori.ts`. У anime365 своя
отсрочка: дважды промолчавший адрес откладывается на десять минут, пять сбоев
подряд выключают источник до конца запуска.

## Видео

### Свой плеер на прямых ссылках

Источники равноправны: каждый отдаёт озвучки, серии и адрес потока, интерфейс
наш целиком. Aniliberty — первый источник: только там прямые ссылки лежат
в открытом API.

```
core/video.ts          типы, реестр, проверка срока, выбор дорожки
  └ api/video-sources.ts единственное место со списком резолверов
      ├ api/aniliberty.ts открытый API, одна озвучка, срока годности нет
      └ api/kodik.ts      цепочка поиск → страница → /ftor, шифр и срок
core/playable.ts       метка доступности: очередь, склад ответов, три состояния
screens/player-view.ts состояние экрана
screens/player-hls.ts  обёртка над hls.js
screens/player-cast.ts кадр за пределами окна
screens/player-input.ts ввод с клавиатуры и пульта
screens/player-keep.ts место остановки и история просмотра
screens/PlayerScreen.vue разметка, заслонка, пропуск заставки
```

Три правила: ядро не знает имён источников; экран не знает, чей поток играет;
ссылки берутся в последний момент. Списки озвучек и серии кэшируются, адреса
потока — никогда.

Место остановки живёт в памяти запуска (`spotKey` = тайтл, озвучка, серия);
первые десять секунд за просмотр не считаются.

### Цепочка Kodik

Шесть шагов, все в `api/kodik.ts`:

1. Поиск: `GET kodik-api.com/search` с токеном и `shikimori_id`, плюс
   `with_seasons`, `with_episodes`, `with_episodes_data`, `with_material_data`.
   Одна озвучка — одна запись поиска.
2. Из адреса страницы регуляркой достаются тип (`seria` или `video`), номер
   и хэш.
3. Страница серии: `domain`, подписи `d_sign`, `pd_sign`, `ref`, `ref_sign`,
   имя связки в `playerLink`. Имя меняется с каждым их выпуском и берётся
   регуляркой из тела страницы.
4. Адрес приёмника и шифр спрятаны в вызовах `atob` со строками base64.
   В коде связка не читается вовсе.
5. `POST` формой на `/ftor`: поля `d`, `d_sign`, `pd`, `pd_sign`, `ref`,
   `ref_sign`, `bad_user`, `cdn_is_working`, `type`, `hash`, `id`. Ответ —
   `links` по качествам, каждое со своим зашифрованным `src`.
6. Расшифровка: сдвиг по латинским буквам с переносом через `z`, затем base64.
   Сдвиг добывается перебором 1..25. Каждое качество расшифровывается
   отдельно: у качеств разные площадки.

`with_material_data=true` добавляет к ответу русское название, описание,
счётчики серий, оценки, жанры, студии — ноль запросов сверх поиска. Берутся
`anime_title` (только с кириллицей), `anime_description`, `episodes_aired`
и `episodes_total`. Постер и кадры не берутся. Сводка живёт только в памяти
запуска.

Поток раздаёт `solodcdn.com`, номер площадки плавает между качествами, поэтому
в разрешениях стоят шаблоны по поддоменам. Заголовки потоку не нужны, CORS
открыт, манифест одиночный (`PLAYLIST-TYPE:VOD`), адреса сегментов
относительные. У части озвучек ключи 480 и 720 ведут на один файл: высотой
берётся меньшая из заявленных.

Срок ссылки — час смерти по Гринвичу, лежит в адресе открытым текстом; час
выдачи округляется вверх. К сроку добавляется запас `STREAM_MARGIN_MS`
(две минуты): ссылка ближе запаса до плеера не дойдёт.

Хрупкое: ссылки подписаны и живут часы; адрес приёмника, шифр и сдвиг
подвижны; имя связки меняется с каждым выпуском; поиск идёт по `shikimori_id`,
а передаётся `idMal` — работает потому, что номера у Шикимори и MAL совпадают.

Плеер — отдельный экран: `player` есть в `SCREEN_NAMES`, адрес
`#/player/<id>`. Зависимость `hls.js` грузится только вместе с экраном
(`defineAsyncComponent`), лёгкой сборкой.

### Состояния отказа

- Ни один источник не знает тайтла — отказ сразу.
- Озвучка есть, серии нет — предложение взять другую озвучку.
- Серия есть, ссылка не вышла — кнопка «Переспросить».

Фатальная ошибка библиотеки доходит до экрана строкой: `player-hls.ts` сам
пробует дважды перезапустить загрузку на сетевых сбоях.

### Кадр за пределами окна

`screens/player-cast.ts` — картинка в картинке и трансляция, оба живут на теге
`<video>`.

1. Remote Playback API: движок сам ищет приёмники и уводит поток. WebView2
   собран без этого умения.
2. Системная панель Windows — команда `animori_cast_panel`, зеркалит весь
   экран. Адреса два по очереди: `ms-actioncenter:controlcenter/CAST`, при
   отказе `ms-settings:connecteddevices`. У каждого адреса два захода: плагин
   `opener`, потом `explorer.exe`.

Порядок шагов: театр складывается перед уходом кадра в окошко; малое окно
закрывается при уходе с экрана; слежение за приёмниками снимается там же;
под заслонкой трансляция разрешена, картинка в картинке нет.

### Метка доступности

Подпись «Есть видео» или «Нет видео» под постером стоит везде, где выбирают,
что смотреть. Состояний три:

- `yes` — хотя бы один источник вернул озвучки;
- `no` — ответили все источники, которым тайтл адресуем (`canAskPresence`),
  и ни один его не знает;
- метки нет — не спрашивали или спросить не вышло.

Сбой не считается «нет»: лежащий источник даёт тот же пустой ответ, что и
отсутствие тайтла.

Очередь вопросов одна на всё приложение (`core/playable.ts`), по работнику на
источник. Очередь молчит до первой отрисовки (`markFirstPaint()`), дальше
пауза `PAINT_REST_MS` (секунда), без сигнала — отсрочка `BOOT_GRACE_MS`
(четыре секунды). Новые вопросы встают в начало. Оптовые источники
спрашиваются пачками по двадцать, штучные по одному (`presenceCost`).
Между шагами пауза `REST_MS` (60 мс). Экран подписан на ответы
(`onPlayableChange`), но не чаще `NOTIFY_MS` (250 мс). Спрошенное не
спрашивается снова: неопределённый ответ уходит в окно тишины `HUSH_TIME_MS`
(10 минут).

Склад ответов — `PLAY1_<номер>` в том же `mediaCache`. Хранится один бит:
вход есть или нет. «Да» держится семь дней, «нет» у идущего тайтла — сутки,
у завершённого — две недели. Неопределённое на диск не пишется.

Цена вопроса у Kodik — запрос на тайтл: оптовой формы у службы нет. Полсотни
плиток отвечают примерно за минуту.

## Остатки манги
