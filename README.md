# AniMori — приложение для AniList

**Настольный клиент [AniList](https://anilist.co) для Windows со своим интерфейсом: списки, поиск, страницы тайтлов и студий, свой плеер — по-русски, без браузера и менеджера скриптов.**

**AniMori** — отдельная программа, которая работает с AniList напрямую: сама запрашивает данные, сама рисует экраны и подтягивает русские названия и описания с Shikimori и anime365.

Прежний десктоп 2.x был устроен иначе — окно с сайтом `anilist.co`, в которое сборка вшивала тот же юзерскрипт. От этой схемы отказались: полный экран, модель фокуса и оформление внутри чужой страницы нам не принадлежали. Версия 3.0 — свой интерфейс от начала до конца.

AniMori — неофициальный проект и не связан с командой AniList.

> [!NOTE]
> **Где что лежит.** У проекта три продукта, и живут они в трёх репозиториях:<br>
> — **`Animori-Desktop`** (этот) — настольное приложение со своим интерфейсом, теги вида `app-3.0.0`;<br>
> — **`Animori-Script`** — юзерскрипт для Tampermonkey, теги вида `script-2.2.0`;<br>
> — **`Animori-TV`** — приложение для Android TV, APK в релизах.<br>
> Ветка в этом репозитории одна — `main`. Сверх приложения в ней лежат замороженная копия словаря перевода для установленных копий скрипта и сторож датасета.

## Состояние

Версия 3.0.1 — текущая. Выпуск в разделе [Releases](https://github.com/foulnike/Animori-Desktop/releases): установщик, портабл-архив и манифест обновлений.

Прежняя гибридная 2.0.2 снята с поддержки и из рабочих веток удалена, но установленные копии перешли на 3.0 сами: идентификатор программы (`com.foulnike.animori`), ключ подписи и адрес манифеста обновлений остались теми же, поэтому первый же тег `app-3.0.0` сдвинул `releases/latest`, и апдейтер внутри старой оболочки предложил обновиться. Настройки и токен лежат в том же профиле и подхватываются новой версией. Подробности — в [`docs/REPO-LAYOUT.md`](docs/REPO-LAYOUT.md).

## Что уже есть

В меню пять разделов — **Главная**, **Моё**, **История**, **Поиск**, **Настройки**. Остальные экраны открываются из них: **Аниме** — из списков и поиска, **Студия** — чипами карточки, **Просмотр** — кнопкой «Смотреть».

- **Русский по умолчанию** — интерфейс написан по-русски; названия и описания подтягиваются с Shikimori или anime365 с указанием источника, а часть имён приезжает готовым датасетом и показывается без сети вовсе.
- **Списки без ожидания** — коллекция держится местным снимком: открывается сразу, работает без сети и не исчезает при отключении счёта.
- **Список остаётся вашим** — ввоз с AniList слиянием или заменой, выгрузка в XML формата MyAnimeList (его примут Шикимори, AniList, Kitsu) и копия в облако, сейчас Яндекс Диск. Правки на сервер не уезжают — [`docs/STORAGE.md`](docs/STORAGE.md).
- **Свой плеер** — отдельный экран на прямых ссылках, без чужого кадра и его рекламы. Источников два: Aniliberty и Kodik. Кадр уходит из окна двумя путями: маленьким окном поверх всех программ или трансляцией на телевизор — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
- **Страница тайтла** — описание и названия по-русски, персонажи и персонал с русскими именами, студии — отдельным экраном, кадры и трейлер — плиткой, музыка — опенинги и эндинги с AnimeThemes полосой внизу окна.
- **Календарь выхода** — на главной, под шапкой: что и когда выйдет у того, что вы смотрите.
- **История** — что смотрели, свежее вперёд; продолжить можно в одно нажатие.
- **Поиск по-русски** — по названиям тайтлов, а также по персонажам и персоналу.
- **Запросы мимо страницы** — к API обращается процесс программы, а не веб-часть: ограничения CORS её не касаются, заголовки под контролем.
- **Прокси** — оболочка применяет прокси из настроек к окну при запуске; панель в настройках показывает исход щупа и живой запрос через канал и предупреждает, что настройка требует перезапуска.
- **Вход в AniList** — в отдельном окне; токен ложится в оболочку и наружу не уходит.
- **Автообновление** — при запуске программа сверяется с последним релизом, проверяет цифровую подпись пакета, ставит обновление и перезапускается.
- **Оболочка** — внешние ссылки уходят в браузер по умолчанию, окно перезагружается кнопкой в шапке. Полный экран оболочка умеет, но кнопки для него в интерфейсе пока нет.

## Чего здесь нет

| Чего нет | Почему |
| :--- | :--- |
| Перевода интерфейса по словарю | у приложения свой интерфейс; `dictionary.json` остался юзерскрипту |
| Отправки правок на AniList | список односторонний, вывоз — файлом или копией в облако |
| Блокировщика рекламы | он имел смысл только внутри окна с чужим сайтом и уничтожен вместе с ним |
| Манги | снята из приложения |
| Юзерскрипта и режимов сборки | конфиг сборки теперь один и безусловный — [`docs/REPO-LAYOUT.md`](docs/REPO-LAYOUT.md) |

## Требования

Windows 10 или 11 и компонент **WebView2** — в Windows 11 и актуальной Windows 10 он уже установлен, иначе установщик предложит его загрузить.

## Сборка из исходников

Нужны Node.js и [окружение Rust и Tauri](https://tauri.app/start/prerequisites/).

```bash
npm install
npm run dev:app        # передний край в браузере
npm run tauri:dev      # окно приложения
npm run build:app      # передний край → dist/app
npm run tauri:build    # установщик → src-tauri/target/release/bundle/nsis/
npm run typecheck:all  # ядро отдельно, затем всё вместе
npm test               # проверки с подменой моста, оболочка не нужна
```

`npm run tauri:build` подписывает пакет обновления, поэтому ждёт переменные окружения `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Свою пару ключей делает `npm run tauri signer generate`.

**Linux.** Нужны те же Node.js и окружение Rust/Tauri плюс системные зависимости WebKitGTK 4.1: для Debian/Ubuntu — `libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`, для Arch/CachyOS — `webkit2gtk-4.1 gtk3 libayatana-appindicator librsvg xdotool`.

```bash
npm install
npm run tauri:build    # установщик → src-tauri/target/release/bundle/deb/
```

Запуск на Wayland-сессии — нативно: приложение само выбирает wayland-бэкенд GTK, когда доступен `WAYLAND_DISPLAY` (X11-сессии не трогает). На проприетарном NVIDIA оно же отключает explicit sync в `run()` — воркэраунд [WebKit bug 324551](https://bugs.webkit.org/show_bug.cgi?id=324551), отдельные переменные не нужны; если GPU-композитинг недоступен, фолбэк `WEBKIT_DISABLE_DMABUF_RENDERER=1` — путь по CPU, медленнее, но работает везде.

Исходники разложены по слоям: `src/shared/` — ядро (API, данные, кэш, мост), `src/app/` — экраны, компоненты и роутер, `src-tauri/` — оболочка на Rust. Ядро про оболочку не знает ничего: `npm run typecheck:shared` проверяет это отдельной сборкой, где каталога `src/app` не существует, и падает на любой стрелке из ядра в надстройку.

## Выпуск

Выпуск делает тег вида `app-3.0.0`: прогон на `windows-latest` сверяет номер в теге с `package.json`, компилирует Rust, собирает установщик, подписывает обновление и кладёт рядом `latest.json`. Описание релиза берётся из верхнего раздела `CHANGELOG.md`.

## Источники данных

| Источник | Назначение |
| :--- | :--- |
| `graphql.anilist.co` | данные и списки AniList |
| `shikimori.rip`, `shikimori.io` | русские названия, описания, персонажи, франшизы (зеркала одного сервиса, опрашиваются по очереди) |
| `smotret-anime.online`, `anime365.ru` | тайтлы и описания (альтернативный источник anime365) |
| `anilibria.top`, `kodik-api.com` | прямые ссылки на видео для своего плеера |
| `graphql.animethemes.moe` | опенинги и эндинги |
| `cloud-api.yandex.net` | облачная копия списка, только по нажатию и только с вашим пропуском |
| `github.com` | манифест обновлений и подготовленные данные (`foulnike/animori-data`) |

Запросы идут из процесса программы. Ваши данные на сторонние серверы не отправляются: токен и настройки остаются на вашей машине, кэш — локальный. Облачная копия уходит только на ваш собственный диск и только тогда, когда вы нажали кнопку. Как собираются подготовленные данные — в [`docs/DATA.md`](docs/DATA.md).
